# AGENTS.md — точка входа для агентов

Общий регламент работы над **bubblegen** для Claude Code и Codex. `CLAUDE.md`
ссылается сюда, других точек входа нет. Правила отсюда старше привычек
инструмента; всё, чего здесь нет, решается по репозиторию, а не по памяти
инструмента.

Уклад тот же, что в пакете bubble (соседняя папка `../bubble`), ради которого
этот проект писался; здесь он пересказан под приложение, которое никуда
не публикуется.

## 1. Начало сессии — восстановление контекста

Сессия может оборваться в любой момент. Порядок восстановления:

1. **`docs/handoff.md`** — состояние **сейчас**: что зелено, что открыто, что
   ждёт решения владельца, какой следующий безопасный шаг. Сюда же идут находки
   и предложения агента.
2. **`docs/backlog.md`** — список владельца: чего он хочет.
3. По необходимости — **`docs/architecture.md`** (как устроены контур и врезки
   и что в них легко сломать) и **`docs/records/`** (история правок).
4. Сверка с репозиторием: `git log --oneline -10`, `git status`.

Пока не прочитан `docs/handoff.md`, никаких правок в коде.

**Код, тесты и git старше любого документа.** Расходится документ
с репозиторием — прав репозиторий. Обратное тоже верно: не переписывать
документ под своё впечатление, не проверив по коду.

## 2. По ходу и в конце сессии — поддержание состояния

**`docs/handoff.md` должен быть актуален всегда**, а не только в конце: сессия
обрывается без предупреждения, и всё, что не записано, теряется. Обновлять его,
когда сделан заметный шаг (коммит, пройденная проверка, найденный дефект),
когда меняется направление работы, перед длинной операцией и в конце сессии —
обязательно.

Чего в нём быть не должно: пересказа истории коммитов (её знает git), разбора
законченных эпизодов (это `docs/records/`) и пожеланий владельца (это
`docs/backlog.md`). Handoff отвечает на «где мы стоим», а не на «как мы сюда
пришли». Волна закончилась — её handoff уезжает в `docs/records/` записью жанра
`report`, а `docs/handoff.md` переписывается под новое состояние.

## 3. Бэклог владельца

`docs/backlog.md` — что владелец хочет сделать с проектом. **Агенты в него
не пишут**: читать — да, брать пункт в работу — да, заводить свои пункты — нет.
Нашли что-то по ходу — в `docs/handoff.md`, а владелец сам решит, переносить ли
это в бэклог. То же с `TODO.txt` в корне: это заметки владельца 2020 года,
агенты его не правят.

Бэклог не пуст, а обязательной работы нет — предложить владельцу взять пункт.
Взятый и доведённый до конца пункт **удаляется из бэклога** в том же коммите,
что и работа; выполненный частично — сокращается до оставшегося. Формулировки
владельца без нужды не переписывать.

## 4. Что это за проект

Flutter-приложение — лаборатория для **bubble 2.0.0**, которая так и не вышла.
Пакет bubble рисует пузырь с хвостиком на одной из сторон; здесь опробован
следующий шаг: контур — прямоугольник со своим радиусом на каждом углу,
а хвостик — врезка, которая заменяет любой участок периметра, в том числе
на углу. Как это устроено — `docs/architecture.md`.

В приложении три вкладки: Generator (пузырь и панель всех его настроек), Bubble
demo (лента пузырей с анимацией) и CustomBubble demo (заглушка).

Код лежит в `lib/` одной папкой, без деления на пакет и приложение:

- `custom_bubble.dart` — контур без хвостика: виджет `CustomBubble`, его
  `RenderBubble`, врезки и позиции на периметре, черновой режим (draft);
- `bubble.dart` — `Bubble` с хвостиком (`Nip`) поверх `CustomBubble`; `NipLine`
  и закомментированная реализация хвостика из ветки `master` — прежний дизайн;
- `geometry.dart` — точки, прямые, отрезки, окружности, касательные;
- `generator.dart`, `bubble_demo.dart`, `main.dart`, `numeric_field.dart`,
  `profiler.dart` — интерфейс;
- `my_painter.dart` — закомментирован целиком, ранняя версия.

Закомментированный код — заметки владельца о том, куда шёл дизайн. Его
не удаляют и не чинят заодно.

Проект не публикуется на pub.dev (`publish_to: none`), репозиторий на GitHub
открытый. Внешних пользователей нет, но **геометрия контура и хвостика —
предмет будущего API bubble**, поэтому её видимое поведение меняется только
по решению владельца. Дефекты записаны в `docs/handoff.md`, решение по ним
за ним.

## 5. Проверки

Тулчейн — **Flutter 3.27.0 через fvm** (`.fvmrc` и `.fvm/` не под контролем
версий), тот же пол, что у bubble: `sdk: ^3.6.0`, `flutter: ">=3.27.0"`. CI
(`.github/workflows/ci.yml`) гоняет те же шаги на 3.27.0 и на свежем stable.

```sh
fvm dart format --set-exit-if-changed lib test
fvm flutter analyze                  # No issues found
fvm flutter test                     # все зелёные; число — в docs/handoff.md
fvm flutter build web                # тесты идут на VM; это настоящая цель
```

Перед коммитом проходят все. Утверждать «работает» без вывода команды нельзя:
сначала прогон, потом заявление.

**Снимки в `test/` — форма контура, снятая с кода 2020 года до первой правки.**
Контур растрирован по центрам пикселей или записан текстом: координаты, вызовы
холста. Тест упал после правки, которая форму менять не должна, — значит, она
её поменяла. Если форма меняется намеренно (решение владельца), снимок
обновляется в том же коммите, и сообщение коммита называет изменение. Тест, для
которого снимка ещё нет, падает и печатает снимок готовым к вставке
(`test/snapshot.dart`).

**Прогнал что-то другим SDK** — через `fvm spawn <версия>` или чужим `flutter`
с `PATH` — сразу после этого `fvm flutter clean && fvm flutter pub get`: чужой
движок оставляет в `.dart_tool` свой кеш, и следующий прогон падает без дефекта
в коде. Проще гонять чужой SDK на клоне (`git clone . <временная папка>`):
тогда проекту чистить нечего.

**Концы строк смешанные** — наследство Windows 2020 года: часть файлов в CRLF
(`git ls-files --eol`), `.gitattributes` нет. Правка сохраняет концы строк
файла. `dart format` их сохраняет, а `dart fix` вставляет в CRLF-файл строки
с LF — после него проверить.

## 6. Как здесь принято работать

- **Сначала тест.** Дефект — сперва падающий тест, потом исправление.
  Исправил — откати правку и убедись, что тест падает.
- **Ожидаемые значения снимаются пробником с живого кода**, а не выводятся
  рассуждением. Тест падает — объяснить почему, а не подгонять ожидание.
- **Не расширяй объём молча.** Нашёл смежную проблему — запиши
  в `docs/handoff.md`, а не чини заодно.
- **Отчитывайся честно.** Тесты упали — покажи вывод.
- **`// ignore:` — только с причиной** в комментарии строкой выше.

## 7. История правок — `docs/records/`

Спеки, планы, отчёты, ревью — сюда, а не в стандартные пути скиллов
(`superpowers:writing-plans` по умолчанию пишет в `docs/superpowers/plans/` —
итог всё равно кладётся в `docs/records/`, второй копии не оставлять).

- Имя файла **`YYYY-MM-DD[N]-name-kind.md`**, квадратные скобки — литеральные;
  `[N]` — порядковый номер записи за день, начиная с `[1]`; дата — дня
  написания.
- **`kind` в конце имени обязателен** — одно слово о том, что это за бумага:
  `design`, `plan`, `report`, `review`. Нужного слова нет — взять своё
  по тому же принципу.
- Каждый файл начинается с H1 и **шапки текущего состояния** под ним:

  ```markdown
  > **Состояние на YYYY-MM-DD:** что с этой работой сейчас — сделано и
  > закоммичено (коммит), брошено, частично сделано, пересмотрено позже.
  > **Что это:** одна фраза о содержимом.
  > **Связанные записи:** имена других файлов в `docs/records/`.
  ```

- Шапку обновляют, когда судьба работы изменилась; сам текст записи
  не переписывают — он исторический.
- Записи в `docs/records/` не поддерживаются как справка: расходятся с кодом —
  верен код.

## 8. Git и GitHub

- Репозиторий **`vi-k/bubblegen`, открытый.** Ветка одна — **`main`**, она же
  ветка по умолчанию. Прежние `master` (`2819ee5`) и `dev` (`0c7b400`) удалены
  2026-10-16: обе целиком входят в историю `main`, а `0c7b400` — коммит,
  от которого `main` начата. Тег `to_bubble_gen` (`b162f0b`) отмечает
  переименование проекта из `bubble_demo`.
- **Не коммить чужие правки вместе со своими.** Перед коммитом — `git status`
  и `git diff`; добавлять в индекс поимённо то, что сделано этим заходом,
  а не `git add -A`. Постороннее в дереве не трогать — ни коммитить,
  ни удалять, — сказать о нём владельцу.
- Сообщения коммитов — по-английски, с префиксом `feat:`, `fix:`, `docs:`,
  `refactor:`, `test:`, `chore:`, `style:`; один фикс — один коммит; тело
  объясняет «почему», а не «что».
- **Push и любые действия на GitHub — только по слову владельца.** Постоянного
  разрешения нет.
- Force-push и переписывание истории — никогда без прямой просьбы.
- CI запускает два задания на каждый push в `main` и раз в неделю
  по расписанию.

## 9. Язык

- Документы (`AGENTS.md`, всё в `docs/`) и общение с владельцем —
  **по-русски**.
- Код, комментарии к новому коду, сообщения коммитов и `README.md` —
  **по-английски**. Русские комментарии 2020 года в коде остаются как есть.
- Русского зеркала README нет. Когда репозиторий был приватным, оно было
  не нужно; заводить ли его теперь — решает владелец (`docs/handoff.md`).

## 10. Чего не делать без слова владельца

- Push и любые действия на GitHub (раздел 8).
- Менять видимое поведение контура и хвостика — в том числе чинить дефекты
  из `docs/handoff.md`.
- Удалять закомментированный код и `TODO.txt`.
- Переносить код в пакет bubble.
- Поднимать пол SDK (`^3.6.0`, Flutter 3.27.0): с языком 3.7 `dart format`
  переходит на высокий стиль, и правило `require_trailing_commas`
  в `analysis_options.yaml` придётся снять.
- Заводить пункты в `docs/backlog.md`.
